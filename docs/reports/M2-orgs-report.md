## 4. Invites (flow, token lifecycle, single-use proof)

- **Create:** `POST /api/orgs/[id]/invites` (admin+, `withOrgRoute` + in-tx `fetchOrgRole` check) → 201 `{url, expiresAt}`. Raw link `<origin>/invite/<token>` returned **exactly once**; only `sha256(token)` stored (unique index). 32-byte `crypto.randomBytes`, base64url. 7-day expiry. Optional email is a display label only — **no emails are sent anywhere** (pilot: copyable links).
- **Accept:** `/invite/[token]` is public (server-guarded): anonymous → `/login?next=/invite/<token>` (sanitized). **GET never mutates** (link/email scanners prefetch): it renders via the `org_invite_preview` definer (zero rows for unknown/expired/used, indistinguishable). Acceptance is a POST server action → `accept_org_invite` SECURITY DEFINER: `UPDATE … WHERE token_hash = $1 AND accepted_at IS NULL AND expires_at > now() RETURNING …` takes the row lock, then inserts the membership (`on conflict do nothing`).
- **Single-use proof:** `tests/orgs/orgs.test.ts` — sequential re-accept → `{ok:false, reason:"invalid_or_used"}`; **parallel double-accept race → exactly 1 winner, 1 membership row**; unknown/expired/revoked all collapse to the same friendly page state (`?used=1` re-entry for the race loser).
- **Revoke:** admin deletes the invite row (`revokeInviteAction` → `revokeInvite`); acceptance afterwards fails.
- Two-fixture API matrix (`tests/api/org-invites.test.ts`): owner 201 (+hash-at-rest proof: stored hash == `hashToken(raw)`, raw absent from the row) · plain member 404 · outsider 404 · foreign org 404 · unauthenticated 401 · bad role/email 400 with nothing stored.

## 6. Quotas (enforcement points, chosen OCR meter, limits)

- Defaults: `max_sessions = 100`, `monthly_ocr_calls = 300` (org_quotas row; missing row → same defaults). Advisory-HARD: enforced on **write paths only**; no read path ever consults quotas. Both gates are cheap COUNTs **inside the caller's request transaction** — nothing slow goes near them.
- **Session create:** `assertSessionQuota(orgId)` in the same tx as membership verification + insert; over limit → `QUOTA_UPGRADE_COPY` ("Contact support to raise limits"), nothing written (proved: limit+1 test). Wizard renders it as the error banner; the org page shows a plan-limits banner.
- **OCR meter — chose `usage_events` (route invocations), NOT match count.** Reason: a match's draft can be re-OCR'd (each re-upload re-invokes the paid Gemini API) while Rondo lobby exports inflate match counts without OCR calls; the API invocation is the thing being limited and metered. One row inserted per **successful** ingest (failed attempts never consume quota — proven by test). Monthly window: `created_at >= date_trunc('month', now())`.
- **OCR route gate:** membership predicate → `assertOcrQuota` → ingest → `recordUsage`, all inside the withUserDb tx; over limit → **409 with the OCR envelope intact**: `{ok:false, error:{code:"QUOTA_EXCEEDED", message, quota:"monthly_ocr_calls"}}`.
- Race tolerance: two concurrent creates can both pass the COUNT (documented "advisory-hard"; the brief accepts this — enforcing strictly would need serialization or atomic conditional inserts).
